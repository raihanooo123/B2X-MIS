---

## 1. Purpose

A quote is a **priced, dated, binding offer** that converts to an order on acceptance.

It exists because wholesale pricing is negotiated. A buyer wanting 40 pallets does not pay list price, and the reference system's answer to that is a telephone number. Every such conversation is an unrecorded price commitment, honoured from memory, with no margin visibility and no audit trail.

This module turns that conversation into a record: who quoted what, at what price, why, with what margin, valid until when, and what happened next.

---

## 2. What the reference system gets wrong

Its negotiation path is "contact us". There is no quote object at all.

| Reference system | Consequence | Requirement here |
|---|---|---|
| Phone or email negotiation | Prices agreed with no record | Persisted quote with snapshotted line prices |
| No expiry | A price quoted last year is still being claimed | Mandatory `expires_at`, enforced |
| No margin visibility at the point of discount | Staff discount below cost without knowing | Live margin per line and per quote, with a floor |
| No approval | Any staff member can concede any price | Discount authority limits with an approval step |
| No conversion path | The agreed order is retyped, introducing errors | One-click conversion; lines carry over exactly |
| No versioning | "We revised that" means the original is lost | Immutable revisions via supersession |
| Not available to prospects | A business must be onboarded before it can be quoted | Quotes attachable to an unapproved applicant |

## 4. State machine

```
  draft ──send──▶ sent ──open──▶ viewed ──▶ accepted ──▶ (order created)
    │               │               │
    │               │               ├──▶ rejected
    │               │               │
    │               └───────────────┴──▶ expired   (scheduled, at expires_at)
    │
    ├──▶ withdrawn            (by owner, before acceptance)
    │
    └──revise──▶ superseded   (a new quote row supersedes this one)
```

| State | Meaning | Editable |
|---|---|---|
| `draft` | Being built. Not visible to the customer | Yes |
| `sent` | Issued. Prices committed | No — revise instead |
| `viewed` | Customer has opened it | No |
| `accepted` | Customer accepted; conversion in progress or complete | No |
| `rejected` | Declined, with an optional reason | No |
| `expired` | Past `expires_at` without a decision | No |
| `withdrawn` | Pulled by the owner | No |
| `superseded` | Replaced by a revision | No |

**A `sent` quote is immutable.** Changing a price means issuing a revision, so what the customer was told is always recoverable. `accepted`, `rejected`, `expired`, `withdrawn` and `superseded` are terminal.

## 5. Schema

Extends the keys committed in Doc 02 §8.4.

### 5.1 `quotes`

```sql
CREATE TABLE quotes (
  id                     bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  public_id              text        NOT NULL,
  quote_number           text        NOT NULL,
  revision               smallint    NOT NULL DEFAULT 1,

  -- audience: an approved company, or a prospect not yet on file
  company_id             bigint      REFERENCES companies (id),
  b2b_application_id     bigint      REFERENCES b2b_applications (id),
  contact_name           text,
  contact_email          citext,
  contact_phone          text,

  requested_by_user_id   bigint      REFERENCES users (id),
  owner_user_id          bigint      NOT NULL REFERENCES users (id),
  origin                 text        NOT NULL DEFAULT 'customer_rfq',
  status                 text        NOT NULL DEFAULT 'draft',

  currency               char(3)     NOT NULL DEFAULT 'GBP',
  subtotal_net_minor     bigint      NOT NULL DEFAULT 0,
  discount_net_minor     bigint      NOT NULL DEFAULT 0,
  shipping_net_minor     bigint      NOT NULL DEFAULT 0,
  tax_minor              bigint      NOT NULL DEFAULT 0,
  total_gross_minor      bigint      NOT NULL DEFAULT 0,
  total_cost_minor       bigint      NOT NULL DEFAULT 0,
  spend_break_id         bigint      REFERENCES order_spend_breaks (id),
  spend_break_discount_minor bigint  NOT NULL DEFAULT 0,
  price_tier_snapshot    text,

  reserve_stock          boolean     NOT NULL DEFAULT false,
  expires_at             timestamptz NOT NULL,
  customer_message       text,
  internal_note          text,

  approval_status        text        NOT NULL DEFAULT 'not_required',
  approved_by_user_id    bigint      REFERENCES users (id),
  approved_at            timestamptz,

  sent_at                timestamptz,
  viewed_at              timestamptz,
  decided_at             timestamptz,
  rejection_reason       text,

  converted_order_id     bigint      REFERENCES orders (id),
  supersedes_quote_id    bigint      REFERENCES quotes (id),
  superseded_by_quote_id bigint      REFERENCES quotes (id),

  created_at             timestamptz NOT NULL DEFAULT now(),
  updated_at             timestamptz NOT NULL DEFAULT now(),

  CONSTRAINT quotes_number_uq          UNIQUE (quote_number),
  CONSTRAINT quotes_public_id_uq       UNIQUE (public_id),
  CONSTRAINT quotes_converted_order_uq UNIQUE (converted_order_id),
  CONSTRAINT quotes_origin_chk CHECK (origin IN
    ('customer_rfq','rep_proactive','basket_conversion')),
  CONSTRAINT quotes_status_chk CHECK (status IN
    ('draft','sent','viewed','accepted','rejected','expired','withdrawn','superseded')),
  CONSTRAINT quotes_approval_chk CHECK (approval_status IN
    ('not_required','pending','approved','rejected')),
  CONSTRAINT quotes_audience_chk
    CHECK (company_id IS NOT NULL OR contact_email IS NOT NULL),
  CONSTRAINT quotes_accepted_chk CHECK (status <> 'accepted' OR decided_at IS NOT NULL)
);

CREATE INDEX quotes_company_created_idx ON quotes (company_id, created_at DESC, id)
  WHERE company_id IS NOT NULL;
-- partial: the expiry sweep and reminder only look at live quotes
CREATE INDEX quotes_open_expiry_idx ON quotes (expires_at)
  WHERE status IN ('sent','viewed');
CREATE INDEX quotes_owner_idx ON quotes (owner_user_id, created_at DESC)
  WHERE status IN ('draft','sent','viewed');
CREATE INDEX quotes_approval_idx ON quotes (created_at)
  WHERE approval_status = 'pending';
CREATE INDEX quotes_contact_email_idx ON quotes (contact_email)
  WHERE contact_email IS NOT NULL;
CREATE INDEX quotes_application_idx ON quotes (b2b_application_id)
  WHERE b2b_application_id IS NOT NULL;
```

**Notes**

- `quotes_converted_order_uq` guarantees **one quote produces at most one order.** A retried acceptance cannot create a second order — the same idempotency pattern as `credit_holds_order_uq` (05.2 §7.1) and `stock_allocations_identity_uq` (02 §7.4).
- `quotes_open_expiry_idx (status, expires_at)` drives the expiry sweep and the pre-expiry reminder. Equality on status, range on date, per Doc 02 §9 rule 7.
- `chk_quotes_audience` permits a quote to a prospect with no `companies` row — the case that lets a large first order be quoted before onboarding completes.
- `quote_number` comes from `number_sequences` (02 §11.3). Revisions share the base number with a suffix: `QUO-000412`, `QUO-000412-R2`.

### 5.2 `quote_lines`

Mirrors `order_lines` (02 §8.3), including the scale discipline — `_e4` per unit, `_minor` per line.

```sql
CREATE TABLE quote_lines (
  id                        bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  quote_id                  bigint   NOT NULL REFERENCES quotes (id) ON DELETE CASCADE,
  line_no                   smallint NOT NULL,
  sku_id                    bigint   NOT NULL REFERENCES skus (id),
  pack_id                   bigint   NOT NULL REFERENCES packs (id),

  sku_code_snapshot         text     NOT NULL,
  name_snapshot             text     NOT NULL,
  pack_label_snapshot       text     NOT NULL,

  pack_qty                  integer  NOT NULL,
  pack_base_units           integer  NOT NULL,
  base_qty                  integer  NOT NULL,

  list_unit_price_e4        bigint   NOT NULL,
  unit_price_net_e4         bigint   NOT NULL,
  line_discount_minor       bigint   NOT NULL DEFAULT 0,
  line_spend_discount_minor bigint   NOT NULL DEFAULT 0,
  line_net_minor            bigint   NOT NULL,
  tax_rate_bp               smallint NOT NULL,
  line_tax_minor            bigint   NOT NULL,
  line_gross_minor          bigint   NOT NULL,

  price_source              text     NOT NULL DEFAULT 'base',
  price_list_id             bigint   REFERENCES price_lists (id),
  price_list_item_id        bigint,
  applied_break_qty         integer,
  override_reason_code      text,

  unit_cost_e4              bigint,
  sku_cost_id               bigint   REFERENCES sku_costs (id),
  margin_bp                 integer,

  is_optional               boolean  NOT NULL DEFAULT false,
  is_accepted               boolean  NOT NULL DEFAULT true,
  lead_time_days            smallint,

  created_at                timestamptz NOT NULL DEFAULT now(),
  updated_at                timestamptz NOT NULL DEFAULT now(),

  CONSTRAINT quote_lines_quote_line_uq     UNIQUE (quote_id, line_no),
  CONSTRAINT quote_lines_quote_sku_pack_uq UNIQUE (quote_id, sku_id, pack_id),
  CONSTRAINT quote_lines_price_source_chk CHECK (price_source IN
    ('contract','customer','promotion','tier','base','manual')),
  CONSTRAINT quote_lines_base_qty_chk CHECK (base_qty = pack_qty * pack_base_units),
  CONSTRAINT quote_lines_override_chk
    CHECK (price_source <> 'manual' OR override_reason_code IS NOT NULL),
  CONSTRAINT quote_lines_tax_chk CHECK (tax_rate_bp BETWEEN 0 AND 10000)
);

CREATE INDEX quote_lines_sku_idx ON quote_lines (sku_id, quote_id);
-- partial: conversion only copies accepted lines
CREATE INDEX quote_lines_accepted_idx ON quote_lines (quote_id) WHERE is_accepted;
```

- `quote_lines_base_qty_chk` is the same keystone pack constraint as on order lines. A quote is a commitment; its arithmetic must be as trustworthy as an order's.
- `list_unit_price_e4` records what the price **would have been** without negotiation, so discount depth is reportable without re-resolving history against price lists that have since changed.
- `chk_ql_override` makes an unexplained manual price structurally impossible.
- `is_optional` / `is_accepted` support partial acceptance (U4).

## 6. Pricing a quote

### 6.1 Build

A quote is built by running the normal engine and then negotiating from the result:

1. Resolve each line per 03 §4 — the customer's real tier, contract and promotion pricing. `list_unit_price_e4` records the resolved figure.
2. Apply the spend-break pass per 03 §7A, snapshotting `spend_break_id` and the apportioned per-line shares.
3. The rep may then override any line's `unit_price_net_e4`, setting `price_source = 'manual'` with a mandatory reason code.
4. Totals recompute through the three-phase sequence of 03 §7A.4 — **tax last**, on post-discount values.

A quote never re-resolves after `sent`. Its prices are snapshots, exactly as order lines are (03 §3.4).

### 6.2 Margin guardrail

Every line shows live margin as the rep types, from the cost snapshot (03 §11):

```
line_margin_minor = line_net_minor − round_half_up(unit_cost_e4 × base_qty / 100)
margin_bp         = line_margin_minor × 10000 / line_net_minor
```

| Condition | Behaviour |
|---|---|
| Margin at or above the configured floor | Proceed |
| Margin below floor, above zero | Warning; permitted with a reason; quote enters `approval_status = 'pending'` |
| Margin at or below zero | **Blocked** unless a manager approves. Selling below landed cost is a decision, not a slip |
| Cost unknown (`unit_cost_e4` IS NULL) | Margin shown as unavailable; flagged on the approval screen |

The floor is configurable globally, per category and per tier, resolved most-specific-first.

Cost figures are visible **only** to rep, manager and admin contexts. `ResolvedPrice::$unitCostE4` is null elsewhere, enforced by policy gate (03 §11) — a customer-facing quote view never carries cost in its payload, not even unrendered.

### 6.3 Discount authority — per rep, per category

Authority is granted **per rep per category**, with a fallback chain. A rep who knows kitchenware can be trusted with deeper concessions there than on electricals, which is how wholesale sales teams actually operate.

```sql
CREATE TABLE rep_category_discount_limits (
  id                    bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  user_id               bigint    NOT NULL REFERENCES users (id) ON DELETE CASCADE,
  category_id           bigint    NOT NULL REFERENCES categories (id) ON DELETE CASCADE,
  max_discount_bp       smallint  NOT NULL,
  max_quote_value_minor bigint,
  granted_by_user_id    bigint    REFERENCES users (id),
  note                  text,
  validity              tstzrange NOT NULL DEFAULT tstzrange(now(), NULL, '[)'),
  created_at            timestamptz NOT NULL DEFAULT now(),
  updated_at            timestamptz NOT NULL DEFAULT now(),

  CONSTRAINT rep_category_discount_limits_discount_chk
    CHECK (max_discount_bp <= 10000),
  CONSTRAINT rep_category_discount_limits_validity_chk CHECK (NOT isempty(validity)),

  -- one live grant per rep per category, enforced by the database
  CONSTRAINT rep_category_discount_limits_no_overlap
    EXCLUDE USING gist (user_id WITH =, category_id WITH =, validity WITH &&)
);

CREATE INDEX rep_category_discount_limits_resolve_idx
  ON rep_category_discount_limits (user_id, category_id)
  INCLUDE (max_discount_bp, max_quote_value_minor, validity);
CREATE INDEX rep_category_discount_limits_category_idx
  ON rep_category_discount_limits (category_id, user_id);
```

**Scale note.** The limit is stored in **basis points** (`max_discount_bp`), not as a percentage, per Doc 02 §2.2 — 15.00% is `1500`. Every rate in the system is bp, and mixing a percentage column into a bp codebase is how a 15% cap silently becomes a 1500% one.

`users.default_max_discount_bp` (nullable) is the per-rep fallback; `roles.default_max_discount_bp` is the role-level floor beneath that.

**Resolution — most specific wins, walking up the category tree.** A line's category is `skus.product_id → products.primary_category_id`. An explicit row on that category wins; failing that, the nearest ancestor with a row; failing that, the rep default; failing that, the role default; failing that, **zero authority** — no discount without approval.

```sql
-- nearest applicable limit for this rep and this line's category
SELECT l.max_discount_bp, l.max_quote_value_minor
FROM   category_closure cc
JOIN   rep_category_discount_limits l
         ON l.category_id = cc.ancestor_id
        AND l.user_id     = :user_id
WHERE  cc.descendant_id = :category_id
ORDER BY cc.depth ASC
LIMIT  1;
```

This is the read the closure table exists for (02 §5.3): `category_closure_descendant_idx (descendant_id, ancestor_id)` gives the ancestor chain as one equality range, joined to `rep_category_discount_limits_resolve_idx`, ordered by depth so the first row is the most specific. No recursive CTE, no tree walk in PHP. A grant on "Kitchen" therefore covers every descendant category automatically, which is what an administrator granting it expects.

Resolved limits are cached per rep, invalidated on any write to the table or to the category tree. Budget: 5 ms cold.

**Evaluation.** Discount depth per line is measured against `list_unit_price_e4`:

```
line_discount_bp = (list_unit_price_e4 − unit_price_net_e4) × 10000 / list_unit_price_e4
```

| Condition | Effect |
|---|---|
| Every line within its category limit, quote value within `max_quote_value_minor` | `approval_status = 'not_required'`; sendable |
| Any line over its category limit | `approval_status = 'pending'`; send blocked |
| Quote value over the limit resolved for the quote's dominant category | `pending` |
| No limit resolves anywhere in the chain | Zero authority. Any discount requires approval |

**Approval is on the quote as a whole, not per line** — a manager approving individual lines while the total remains unviable is theatre. The approval screen shows total value, blended discount depth, blended margin, every line over its authority (with the limit that applied and where it was resolved from), and every line below the margin floor.

Authority is independent of the margin guardrail in §6.2. Both must pass: a rep may have 20% authority on a category whose margin floor a 20% discount would breach, and the floor still blocks it. Authority governs *what the rep may concede*; the floor governs *what the business will accept*.

`quotes_approval_idx (approval_status, created_at)` drives the queue. Grants and revocations are written to the audit log with `granted_by_user_id`.

## 7. Stock and credit

### 7.1 Quotes do not reserve stock by default

`reserve_stock` defaults to `0`. Reasoning: quotes are speculative and many are outstanding at once. Reserving stock against every quote would make the warehouse appear empty while nothing is actually sold — which is worse than the problem it solves.

When a rep sets `reserve_stock = 1` (for a committed large order awaiting a purchase order number, say):

- Allocation runs the standard 04 §4.2 path at send time, with `reference_type = 'quote'`.
- The reservation expires with the quote. The stale-allocation reaper (04 §9) releases it at `expires_at`, using `quotes_open_expiry_idx`.
- The quote document states that stock is held and until when, because that is the value the customer is being given.

Stock availability is **shown** on every quote line either way, as an indication with an explicit note that it is not reserved unless stated.

### 7.2 Credit is checked at acceptance, not at quote time

A quote is an offer, not an order. Checking credit at quote time would block quoting a customer whose current exposure is high but who intends to pay down before accepting.

At acceptance the full 05.2 §8 check runs, in the 05.2 §8.2 lock order. A quote can therefore be accepted and land at `awaiting_approval` or require prepay. The acceptance screen states this before the customer commits, rather than after.

## 8. Conversion to order

One transaction, at acceptance:

```
BEGIN;   -- lock order per 05.2 §8.2: companies, then stock_levels ascending

  1. Re-verify quote status = sent | viewed, and NOW() <= expires_at
  2. Copy accepted lines (is_accepted = 1) to order_lines, preserving:
       unit_price_net_e4, tax_rate_bp, pack_id, pack_qty, base_qty,
       price_source, price_list_item_id, applied_break_qty,
       spend_break_id and the apportioned per-line shares
  3. Refresh unit_cost_e4 from current sku_costs   ← cost is current, price is quoted
  4. Credit check + credit_holds insert            (05.2 §8)
  5. Allocate stock                                (04 §4.2)
  6. quotes.status = 'accepted', decided_at, converted_order_id
COMMIT;
AFTER COMMIT: order confirmation, quote PDF attached to the order record
```

**Two details that matter.**

**Quoted prices are honoured; costs are refreshed.** The customer pays what they were quoted, even if list prices have risen — that is what a quote is. But margin must reflect what the goods actually cost now, so `unit_cost_e4` is re-snapshotted. If this turns the order margin negative, the conversion completes and the rep and manager are notified: the commitment is kept, the loss is visible, and it informs the next quote.

**Partial acceptance produces one order for the accepted lines.** Declined optional lines stay on the quote, which moves to `accepted` with a record of what was taken. It does not spawn a residual quote — a customer who later wants the rest asks again, and gets current pricing rather than an indefinite option.

Conversion failures — expired between view and click, stock gone, credit refused — return a specific reason. The quote stays in its prior state so it can be revised rather than lost.

## 9. Revisions

Revising a `sent` quote creates a **new row**:

```
new.supersedes_quote_id = old.id
new.revision            = old.revision + 1
new.quote_number        = old base number with -R{revision}
old.status              = 'superseded'
old.superseded_by_quote_id = new.id
```

Lines are copied and then edited. The original is untouched and remains readable — which is the point. "What did we actually offer them in March?" must be answerable.

The customer sees the current revision, with earlier ones accessible in the history.

## 10. Expiry and follow-up

| Job | Frequency | Action |
|---|---|---|
| Expiry sweep | Hourly | `sent`/`viewed` past `expires_at` → `expired`; release stock reservations |
| Pre-expiry reminder | Daily | Notify owner 3 days before expiry; notify customer 1 day before |
| Stale draft sweep | Weekly | Flag `draft` quotes untouched for 30 days to their owner |

Default validity is 30 days, configurable, and always explicit on the document. An open-ended quote is a price the business can be held to indefinitely.

## 11. The quote document

A generated PDF, attached to the quote and emailed:

- Quote number and revision, issue date, **expiry date prominently**
- Customer and contact details; the rep as named contact
- Per line: SKU code, name, pack, quantity, unit price, line total. Optional lines marked
- Subtotal, spend-break discount if any, shipping, VAT, total
- Terms: payment terms, delivery or collection basis, lead times, stock-reservation statement
- Accept and decline links (tokenised, no login required — a quote may go to someone without an account)

Never shows cost or margin. Generated on a queue, not in the request.

## 13. Edge cases

| Case | Behaviour |
|---|---|
| Quote expires between the customer viewing and clicking accept | Acceptance refused with the expiry stated; owner notified so it can be reinstated as a revision |
| SKU discontinued after sending | Flagged at acceptance; that line cannot convert. Customer chooses to proceed without it or await a revision |
| Pack deleted after sending | Line falls back to the default sell pack with `base_qty` preserved; change shown at acceptance |
| Cost rises so the quoted price is now below cost | Conversion proceeds; rep and manager notified with the margin figure |
| Prospect quote accepted before account approval | Order created with `company_id` NULL and prepay required; the order links to the application and attaches on approval |
| Two users accept the same quote simultaneously | `quotes_converted_order_uq` ensures exactly one order |
| Rep leaves; quotes still open | Reassignment action moves ownership; `owner_user_id` history retained in the audit log |
| Customer accepts, credit refused | Order created at `awaiting_approval`; quote is `accepted`; accounts notified. The acceptance is not silently discarded |
| Quote built at an old tier, customer since re-tiered | Quoted prices stand. That is the commitment |
| Spend break expires between send and acceptance | The snapshotted discount stands; spend breaks are part of the quoted price |

## 14. Test matrix

**Workflow fixtures:** RFQ from basket → rep prices → sends → customer accepts → order created with identical line values · rep proactive quote to a prospect with no company → accepted → prepay order · revision chain of three, each readable, only the latest live · partial acceptance converting only accepted lines · expiry sweep transitioning and releasing reserved stock · below-floor discount requiring and receiving approval · below-cost discount blocked without approval · acceptance refused on expiry, quote revisable afterwards.

**Numeric:** for 1,000 generated quotes, `Σ line_net_minor + shipping + Σ line_tax = total_gross_minor` exactly · converted `order_lines` are field-for-field identical to accepted `quote_lines` for every price and pack field, with only `unit_cost_e4` differing · discount depth computed from `list_unit_price_e4` matches the reported figure.

**Concurrency:** Q1 two simultaneous acceptances produce exactly one order · Q2 acceptance racing the expiry sweep resolves cleanly either way, never both · Q3 acceptance racing another order from the same company against a shared credit limit serialises per 05.2 §8.2 with zero deadlocks.

**Authorisation:** cost and margin absent from every customer-facing payload, verified by response inspection, not by view review · a rep cannot send a quote exceeding their authority · a rep cannot approve their own quote.

**Discount authority resolution:** explicit category row wins over ancestor row · ancestor grant on "Kitchen" applies to every descendant category · rep default used when no category row exists anywhere in the chain · role default used when no rep default · **no row anywhere means zero authority**, not unlimited · a quote spanning three categories is evaluated per line against each line's own resolved limit · resolution query uses `category_closure_descendant_idx` with no recursive CTE, asserted by `EXPLAIN`.

## 15. Acceptance criteria

1. A quote can be built, priced, discounted with reasons, approved, sent, viewed and accepted, with every transition timestamped and attributed.
2. Converted order lines are field-for-field identical to accepted quote lines on all price and pack fields; only `unit_cost_e4` is refreshed.
3. `quotes_converted_order_uq` verified: 100 simultaneous acceptances of one quote produce exactly one order.
4. Margin is live per line during editing, and the floor blocks below-cost pricing without manager approval.
5. Cost and margin never appear in any customer-facing response payload.
6. Quotes expire on schedule; reserved stock is released on expiry.
7. Revisions preserve every prior version as readable, with exactly one live.
8. A prospect with no `companies` row can be quoted and can accept, producing a prepay order linked to their application.
9. Partial acceptance converts only accepted lines, with the declined lines recorded.
10. Credit refusal at acceptance produces an order at `awaiting_approval` rather than discarding the acceptance.
